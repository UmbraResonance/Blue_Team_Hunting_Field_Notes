## Tcpdump (Live Capture & Triage)
*Use Case: Native tool available on almost all *nix systems. Ideal for rapid on-box triage and line-speed capturing.*

### Basic Operations
**Standard Triage Capture (No DNS, Verbose, ASCII/Hex):**
```bash
tcpdump -i <INTERFACE> -nnvv -X -c 100
```

**Read from PCAP with Absolute Sequence Numbers:**
```bash
tcpdump -r <PCAP_FILE> -S
```

### Live Analysis Pipelines
**Piping to Grep (Line-Buffered):**
*Crucial for real-time keyword hunting in high-traffic streams.*
```bash
tcpdump -i <INTERFACE> -A -l | grep -i "password"
```

### Advanced BPF (Byte Offset) Filtering
*Reference: See 01_Hunting_Cheatsheets/1.4_Network_Protocol_Filters.csv for protocol-specific offsets.*

**Filter for SYN-only packets (Potential Port Scan):**
```bash
tcpdump -i <INTERFACE> 'tcp[13] & 2 != 0 and tcp[13] & 16 == 0'
```

**Filter for HTTP GET requests (Manual payload inspection):**
```bash
tcpdump -i <INTERFACE> -s 0 -A 'tcp[((tcp[12] & 0xf0) >> 2):4] = 0x47455420'
```

## Tshark (Command Line Wireshark)
*Use Case: PCAP is too large (>500MB) for Wireshark, or you need to grep specific fields.*

### Triage & Statistics

**Protocol Hierarchy (What's in this PCAP?):**
```bash
tshark -r <PCAP_FILE> -q -z io,phs
```
**Top Talkers (Who is connecting?):**
```bash
tshark -r <PCAP_FILE> -q -z conv,ip
```

**Conversation List (Detailed Flows):**
```bash
tshark -r <PCAP_FILE> -n -z conv,tcp
```

### Hunting & Filtering

**Extract HTTP Host Headers (Which sites were visited?):**
```bash
tshark -r <PCAP_FILE> -Y "http.request" -T fields -e http.host | sort | uniq -c | sort -nr
```

**Extract DNS Queries (C2 Domains?):**
```bash
tshark -r <PCAP_FILE> -Y "dns.flags.response == 0" -T fields -e dns.qry.name | sort | uniq -c | sort -nr
```

**Extract User Agents (Spot tools like Nmap/Sqlmap):**
```bash
tshark -r <PCAP_FILE> -Y "http.user_agent" -T fields -e http.user_agent | sort | uniq -c
```

### Traffic Slicing (Carving)

*Action: Extract attacker's traffic to a new, smaller PCAP for Wireshark analysis.*

```bash
tshark -r <FULL_PCAP> -Y "ip.addr == <ATTACKER_IP>" -w attacker_traffic.pcap
```

## NetworkMiner (Automated Extraction)

*Use Case: "Lazy" extraction of files, images, and credentials without crafting filters. Note: NetworkMiner runs on Windows (or via Mono on Linux).*

**Key Tabs to Check (BTL1 Priority):**
- **Files:** Automatically reassembles .exe, .pdf, .docx from the stream.
    - Action: Right-click file -> "Open Folder" -> Calculate Hash immediately.
- **Credentials:** Auto-extracts cleartext (FTP, HTTP Basic, POP3, IMAP).
- **Images:** Reconstructs images (useful for finding "confidential" screenshots exfiltrated).
- **Parameters:** Shows extracted HTTP GET/POST parameters (great for spotting SQLi/XSS payloads).

## Wireshark GUI Workflows (Setup & Config)

*Configuration steps that aren't "filters" but are critical for analysis.*

### C2 Jitter Analysis (Time Delta)

*Goal: Detect automated beaconing (e.g., malware phoning home exactly every 5.0 seconds).*

- Menu: View -> Time Display Format -> Seconds Since Previous Displayed Packet.
- Filter: Apply ip.addr == <C2_IP>.
- Sort: Click the "Time" column header.
- Analyze: Look for consistent patterns (e.g., 5.002, 5.010, 4.998).

### Column Customization (Data Exfiltration)

*Goal: See data size directly in the packet list.*

- Right-click Column Header -> Column Preferences.
- Add Column:
    - Title: Packet Length
    - Type: Packet length (bytes)
- Use Case: Sort by Length to find the largest packets (potential file uploads).

### Export Objects (File Recovery)

*Goal: Save a file from HTTP/SMB streams.*

- HTTP: File -> Export Objects -> HTTP -> Save specific file.
- SMB: File -> Export Objects -> SMB/SMB2 -> Save file.

## Zeek (Network Security Monitoring & Log Analysis)

*Use Case: Transforming raw PCAPs into highly structured, protocol-specific logs for rapid threat hunting and DFIR. Ideal for detecting behavioral anomalies rather than relying on static signatures.*

### PCAP Processing & Log Generation
*Goal: Read an offline PCAP file and generate Zeek TSV logs in the current directory. The `-C` flag is critical as it tells Zeek to ignore invalid TCP/UDP checksums (which is extremely common and necessary when analyzing recorded PCAPs).*

```bash
/usr/local/zeek/bin/zeek -C -r <PCAP_FILE>
```

### Log Parsing Essentials (`zeek-cut`)
*Goal: Extract specific columns from TSV logs efficiently, bypassing the need to manually strip headers. Acts similarly to Splunk's `| table`.*

**Basic Column Extraction:**
```bash
cat conn.log | /usr/local/zeek/bin/zeek-cut id.orig_h id.resp_h id.resp_p proto
```

**Handling Compressed Rotated Logs:**
*Crucial for querying historical traffic archives without extracting them first.*
```bash
zcat conn*.log.gz | /usr/local/zeek/bin/zeek-cut ts id.orig_h id.resp_h | head -n 20
```

### Hunting Scenarios & Pipelines

#### Detecting C2 Beaconing (Intervals & Payloads)
*Target Log: `conn.log`*
*Goal: Spot consistent connection intervals and static payload sizes indicating automated check-ins.*

**Review connections to a suspicious IP for uniform timing and byte counts:**
```bash
cat conn.log | grep "<SUSPICIOUS_IP>" | /usr/local/zeek/bin/zeek-cut ts orig_bytes resp_bytes conn_state
```
*(Analysis tip: Calculate the delta between the Unix timestamps `ts`. A perfectly consistent 5-second or 10-second gap, combined with identical `orig_bytes` and `resp_bytes`, is a strong beaconing indicator.)*

#### Detecting DNS Exfiltration / Tunneling
*Target Log: `dns.log`*
*Goal: Identify anomalous volumes of highly unique, long, and randomized subdomains queried to a single root domain.*

**Extract, clean, and count top queried domain structures:**
```bash
cat dns.log | /usr/local/zeek/bin/zeek-cut query | cut -d . -f1-7 | sort | uniq -c | sort -nr | head -n 20
```

#### Detecting TLS Data Exfiltration (Volume Aggregation)
*Target Log: `conn.log`*
*Goal: Find endpoints uploading massive amounts of data over encrypted channels when payload inspection is impossible.*

**Group by Source and Destination IP, sum the outbound bytes, and sort descending (requires `datamash`):**
```bash
cat conn.log | /usr/local/zeek/bin/zeek-cut id.orig_h id.resp_h orig_bytes | sort | grep -v -e '^$' | grep -v '-' | datamash -g 1,2 sum 3 | sort -k 3 -rn | head -n 10
```

**Alternative using native `awk` (if `datamash` is unavailable in the environment):**
```bash
cat conn.log | /usr/local/zeek/bin/zeek-cut id.orig_h id.resp_h orig_bytes | awk '{if($3 != "-") sum[$1" -> "$2]+=$3} END {for(i in sum) print i, sum[i]}' | sort -k 4 -rn | head -n 10
```

#### Lateral Movement via PsExec
*Target Logs: `dce_rpc.log`, `smb_files.log`, `smb_mapping.log`*
*Goal: Track malicious service creation and binary transfers across the network without relying on endpoint event logs.*

**Hunt for suspicious RPC calls tied to service manipulation:**
```bash
cat dce_rpc.log | /usr/local/zeek/bin/zeek-cut id.orig_h id.resp_h endpoint operation | grep "svcctl"
```
*(Analysis tip: Look for the sequence `OpenSCManagerW` -> `CreateServiceWOW64W` -> `StartServiceW`. Cross-reference `smb_files.log` for concurrent transfers of `.exe` files to the `ADMIN$` share).*

## Snort

*Use Case: Running historical network traffic against a set of static IDS rules to identify known malicious signatures and generate alerts.*

### PCAP Processing & Alert Generation

*Goal: Process the traffic through Snort's rule engine using a specific configuration file.*

```bash
snort -c /etc/snort/snort.conf -r <PCAP_FILE>
```
## Suricata

*Use Case: Modern, multi-threaded alternative to Snort. Excellent for processing large PCAPs against complex rule sets (like Emerging Threats) and generating rich, structured JSON telemetry (Eve logs).*

### Basic PCAP Analysis:

*Goal: Keep analysis artifacts isolated for a specific investigation.*

```bash
suricata -c /etc/suricata/suricata.yaml -r <PCAP_FILE> -l ./suricata_logs/
```

### Extract Specific Alert

```bash
cat ./suricata_logs/eve.json | jq 'select(.event_type=="alert" and (.alert.signature | contains("<Key_Word>")))
```
