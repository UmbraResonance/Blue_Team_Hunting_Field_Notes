# Portable Executable (PE) Architecture

## 1. Core Concept
The PE format is the standard data structure for executable files, object code, DLLs, and kernel modules in Windows. It dictates how the Windows OS Loader maps the binary from disk into the Virtual Address Space (VAS) of a process.

## 2. Critical PE Sections (The "W^X" Principle)
* **`.text` (Code Section)**: Contains executable machine instructions. Expected permissions: `Read` + `Execute` (R-X). *Hunting Red Flag: `Write` + `Execute` (RWX) indicates potential self-modifying code or unpacking.*
* **`.data`**: Initialized global/static variables. Expected permissions: `Read` + `Write` (RW-).
* **`.rdata`**: Read-only data, string literals, and often the Import Directory. 
* **`.bss`**: Uninitialized data. Takes up zero space on disk (Raw Size = 0) but is allocated in memory.
* **`.rsrc`**: Resources (icons, version info). *Hunting Red Flag: High entropy data hidden here may indicate an encrypted payload.*
* **`.reloc`**: Relocation table necessary for Address Space Layout Randomization (ASLR) and Reflective DLL Loading.

## 3. Imports and Exports
* **Import Directory (`.idata`)**: Lists external DLLs and functions the binary relies on (e.g., WINAPI calls).
    * **Imphash (Import Hash)**: An MD5 hash of the ordered import list. Crucial for clustering malware families.
* **Export Directory (`.edata`)**: Exposes internal functions for other modules to call. Mandatory for legitimate DLLs.
