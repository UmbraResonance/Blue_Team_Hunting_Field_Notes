# Application Compatibility Subsystem (AppCompat)

> **Core Concept:** Windows uses the Application Compatibility subsystem (Shims) to ensure legacy software runs on modern OS versions. 
> **Blue Team Impact:** The artifacts generated by this subsystem (ShimCache and Amcache) are high-fidelity sources for proving **Execution History (T1059)** and retrieving binary metadata (hashes) even after a file is deleted.

---

## 1. Technical Architecture

When a process is launched, the Windows Loader (`ntdll.dll`) checks if the executable requires any compatibility fixes before passing control to the application.

### **1.1 The Execution Workflow**
1. **Process Initiation:** A user or system attempts to execute a binary.
2. **Compatibility Check:** The OS queries the Shim Engine (via `apphelp.dll`) to see if the executable matches any known compatibility flags.
3. **Cache Updating:** * **ShimCache (AppCompatCache):** The system temporarily logs the file path, last modified time, and execution flag in memory. Upon shutdown, this memory is flushed to the `SYSTEM` registry hive.
   * **Amcache:** The system records deep metadata, including the file's SHA1 hash, publisher, and compile time, directly into `Amcache.hve`.

### **1.2 Artifact Components**
* **ShimCache**:
    * **Role**: Tracks executable paths and their Last Modified (not execution) timestamps. 
    * **Limitation**: Does not explicitly prove an application successfully executed, only that Windows evaluated it for compatibility.
    * **Location**: `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\AppCompatCache`
* **Amcache**:
    * **Role**: Stores detailed inventory of applications and drivers.
    * **Forensic Value**: Contains the SHA1 hash of the executable. This is critical for threat intel pivoting when the original malware binary has been securely wiped from the disk.
    * **Location**: `C:\Windows\AppCompat\Programs\Amcache.hve`

## 2. Adversary TTPs

### **Scenario A: Anti-Forensics and Timestomping (T1070.006)**
* **Mechanism:** Adversaries may use tools to alter the Last Modified timestamp of a malicious payload before execution (Timestomping).
* **Impact:** Because ShimCache records the file's Last Modified time at the moment of evaluation, the cache will reflect the forged timestamp, potentially breaking the analyst's timeline if not correlated with the `$MFT`.

### **Scenario B: Cache Clearing (T1070.004)**
* **Mechanism:** Attackers may attempt to clear the AppCompat keys in the registry or delete the `Amcache.hve` file to hide their execution tracks.

| Red Flag | Description | Correlation |
| :--- | :--- | :--- |
| **Orphaned Hashes** | An Amcache entry with a known malicious SHA1, but the physical file is absent from the disk. | Cross-reference with `AmcacheParser` output in [[6.02_Windows_DFIR_Master_Notes]]. |
