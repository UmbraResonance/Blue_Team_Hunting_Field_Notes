# 8.1.18 NTFS Architecture and File System Internals: A DFIR Perspective

> **Core Concept:** Understanding NTFS is not just about knowing how files are stored; it's about tracking a file's complete lifecycle—from how it entered the network, how the kernel allocated space for it, how attackers attempt to hide it, and how we reconstruct its history.

## Phase 1: File Arrival & Provenance (MotW)
When a file first drops onto a system, Windows attempts to tag its origin before it even executes.
* **Alternate Data Streams (ADS):** NTFS allows data to be attached to a file without altering its primary content.
* **Mark of the Web (MotW):** The Attachment Execution Service (AES) uses ADS to tag downloaded files with `ZoneId=3` (Internet).
* **Adversary Bypass:** Attackers frequently use container formats (ISOs, VHDs) or obscure archiving tools specifically to attempt to bypass these MotW tags during payload delivery.

## Phase 2: Physical Allocation (The MFT)
Once the file is saved, NTFS creates a master record to manage it. 
* **The 1024-byte Record Rule:** Every file corresponds to a fixed 1024-byte entry in the Master File Table (MFT), consisting of a Header and various Attributes.
* **Resident vs. Non-Resident Data (`$DATA` / `0x80`):** * If a file's payload is small enough (typically < ~700 bytes), the actual content is stored directly inside the MFT (Resident), which explains why these payloads remain intact within the MFT even after file deletion.
  * Larger files have their data stored elsewhere on the disk, making them Non-Resident.
* **Anti-Forensics TTP:** Attackers may intentionally pad files to force Non-Resident allocation.
* **Lifecycle Tracking:** The Entry ID and Sequence Number track the file's lifecycle and monitor record reallocation.

## Phase 3: State Mechanics & Timestomping (The Attribute Dualism)
As the file lives on the disk, its state changes are recorded via timestamps. 
* **MAC(b) State Machine:** NTFS tracks Modified (M), Accessed (A), Changed (C - MFT Metadata), and Birth (b) times. By comparing expected timestamp behaviors (File Creation vs. File Copy vs. File Modification), analysts can build a timeline.
* **Hunting Heuristic:** Highlighting anomalies, such as a 'Modified' time being significantly older than the 'Birth' time, can act as an indicator of dropped/copied payloads.
* **The Dual Attributes:** NTFS stores timestamps in two separate attributes: `$STANDARD_INFORMATION` (SIA / `0x10`) and `$FILE_NAME` (FNA / `0x30`).
* **Timestomping (T1070.006):** * *The Exploit:* Attackers modify the SIA attribute via API to obfuscate creation dates.
  * *The Detection:* FNA timestamps are strictly managed by the kernel. Discrepancies between the SIA and FNA timestamps serve as a high-fidelity indicator of Timestomping (T1070.006).

## Phase 4: Historical Trajectory (USN Journal)
While the MFT tells us the current state of the file, the journal tells us what happened to it.
* **State vs. Event Analysis:** Differentiating state-based analysis (`$MFT`) from event-based analysis (`$J`) is crucial.
* **Lineage Tracking:** The Update Sequence Number (USN) Journal (`$J`) allows analysts to trace file lineage (e.g., `.crdownload` -> `malware.exe`).
