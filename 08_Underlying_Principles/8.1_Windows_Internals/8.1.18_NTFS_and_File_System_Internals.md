# NTFS Architecture and File System Internals

## 1. Master File Table (MFT) Anatomy
- The 1024-byte Record Rule: Header vs. Attributes.
- Entry ID & Sequence Number: Tracking file lifecycle and record reallocation.
- Resident vs. Non-Resident Data ($DATA / 0x80):
  - Why payloads < ~700 bytes remain intact within the MFT even after file deletion.
  - Anti-forensics considerations (padding files to force Non-Resident allocation).

## 2. Timestamps and MAC(b) State Machine
- Definitions: Modified (M), Accessed (A), Changed (C - MFT Metadata), Birth (b).
- Expected Timestamp Behavior (Table):
  - File Creation vs. File Copy vs. File Modification.
- Hunting Heuristic: Highlighting anomalies (e.g., 'Modified' time being significantly older than 'Birth' time as an indicator of dropped/copied payloads).

## 3. The Attribute Dualism: Timestomping Detection
- $STANDARD_INFORMATION (SIA / 0x10) vs. $FILE_NAME (FNA / 0x30)
- The Exploit: Attackers modify SIA via API to obfuscate creation dates.
- The Detection: FNA timestamps are strictly managed by the kernel. Discrepancies between SIA and FNA serve as a high-fidelity indicator of Timestomping (T1070.006).

- How payload delivery mechanisms (ISOs, VHDs, specific archiving tools) attempt to bypass MotW.
