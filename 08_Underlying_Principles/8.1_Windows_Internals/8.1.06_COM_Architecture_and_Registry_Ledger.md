# COM Architecture, RPCSS & Registry Ledger

> **Core Principle**: Component Object Model (COM) is the functional framework of Windows. The Registry acts as the "Static Ledger" used to index and activate these capabilities, while RPCSS acts as the active orchestrator.

## 1. Core Identity IDs
* **GUID**: Global Unique Identifier; the universal "ID Card" for everything in Windows.
* **CLSID (Class ID)**: The **Functional ID**. Defines *what* the component does (e.g., "PDF Thumbnail Handler").
* **AppID (Application ID)**: The **Security Policy**. Defines *who* can run it and the **Access Token** context used.
* **ProgID (Programmatic Identifier)**: A human-readable string (e.g., `Word.Document`) mapped to a CLSID, primarily used by applications for easier instantiation.

## 2. RPCSS: The COM Foreman
The **Remote Procedure Call Service (RPCSS)** is the central subsystem responsible for COM orchestration:
* **Activation**: Finding the CLSID in the registry and determining the correct execution path.
* **Resolution**: Prioritizing `HKCU` (HKEY_CURRENT_USER) over `HKLM` (HKEY_LOCAL_MACHINE). This is a deliberate OS design choice to allow individual users to have custom application settings, shell extensions, and roaming profiles without requiring local administrator privileges.
* **Management**: Spawning and managing isolated processes for out-of-process COM objects.

## 3. Dynamic Activation Paths (The Registry Ledger)
When `CoCreateInstance` is called, RPCSS consults the registry to determine *how* the COM object should be loaded. Windows uses several different subkeys under a CLSID or ProgID to define these activation paths:

* **`InprocServer32` (In-Process)**: Instructs the system to load a `.dll` directly into the Virtual Address Space (VAS) of the calling application. Designed for lightweight extensions (like Windows Explorer thumbnail generators) that need high-performance, shared-memory access.
* **`LocalServer32` (Out-of-Process)**: Instructs the system to spawn an independent `.exe`. Designed for standalone applications exposing COM interfaces (e.g., Microsoft Excel) so a crash in the COM object does not bring down the calling application.
* **`TreatAs` (Component Forwarding)**: A registry key that points one CLSID to another. Architecturally designed for backward compatibility, allowing developers to smoothly upgrade a COM component by redirecting calls from an old legacy CLSID to a newer version.
* **`shell\verb\command` (Shell Execution)**: Typically associated with ProgIDs or file extensions. It defines the exact command-line execution string triggered when a user performs a shell action (like right-clicking a file and selecting "Open" or "Print").

## 4. Surrogate Processes (`dllhost.exe`)
Not all DLLs are safe or stable enough to be loaded directly into a critical caller's process (via `InprocServer32`). When a COM object needs to run out-of-process for stability or security isolation, RPCSS hosts it within a **COM Surrogate**.
* **Standard Behavior**: `dllhost.exe` is the default surrogate. It is launched cleanly by the DCOM Launch service (`svchost.exe -k DcomLaunch`).
